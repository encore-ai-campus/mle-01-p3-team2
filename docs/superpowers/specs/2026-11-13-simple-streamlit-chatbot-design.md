# Simple Streamlit Chatbot Design

## Intent

현재 프로젝트의 농업 GraphRAG Supervisor를 사용자가 웹 화면에서 질문할 수 있도록, 기존 기업 정보용 Streamlit 구현을 최소 기능 챗봇으로 교체한다.

## Goals

- `scripts/run_supervisor.py`의 `build_app()`을 재사용해 현재 Supervisor 실행 흐름과 동일한 답변을 생성한다.
- Streamlit 리소스 캐시로 Supervisor 앱과 Neo4j 드라이버를 한 번만 생성한다.
- 사용자 메시지와 챗봇 답변을 세션 동안 유지한다.
- 질문 입력창과 대화 초기화 기능을 제공한다.
- Supervisor 결과의 `final_answer`를 챗봇 답변으로 표시한다.
- 설정 누락, Neo4j 연결 실패, 실행 오류를 사용자가 이해할 수 있는 화면 메시지로 표시한다.

## Non-goals

- 그래프·지도·통계·기업 정보 화면을 유지하거나 새로 구현하지 않는다.
- 검색 경로, 근거 목록, 내부 Supervisor 상태를 시각화하지 않는다.
- 여러 대화방, 사용자 인증, 답변 스트리밍, 장기 대화 기억을 구현하지 않는다.
- Supervisor 자체의 검색·라우팅·답변 생성 로직을 변경하지 않는다.

## Constraints

- 실행에는 기존과 동일하게 `.env`의 Neo4j 설정이 필요하다.
- Streamlit 재실행 시에도 세션 메시지를 보존하되, 앱 프로세스 종료 후 영구 저장하지 않는다.
- Neo4j 드라이버는 캐시된 리소스에 포함되므로 매 질문마다 닫지 않는다.
- 기존 기업용 코드와 테스트는 현재 프로젝트에 맞지 않으므로 새 최소 UI의 실행 경로에서 제거한다.

## Approaches

1. **기존 실행 모듈 재사용 — 선택됨.** 변경 범위가 작고 CLI와 동일한 동작을 즉시 재사용할 수 있다. 대신 UI가 `scripts` 모듈에 의존한다.
2. **공용 런타임 모듈로 분리.** 구조는 더 깔끔하지만 단순 챗봇이라는 이번 범위를 넘어선다.
3. **CLI 하위 프로세스 호출.** 결합은 약하지만 시작 비용과 오류 처리가 불리해 제외한다.

## UI and behavior

- 페이지 제목과 안내 문구는 프로젝트의 농업 질의응답 용도를 드러낸다.
- 저장된 메시지를 `st.chat_message`로 순서대로 표시한다.
- `st.chat_input`으로 받은 공백이 아닌 질문을 사용자 메시지에 추가한다.
- 답변 생성 중에는 spinner를 표시한다.
- `app.invoke({"question": question})` 결과에서 `final_answer`를 읽어 답변으로 저장하고 표시한다.
- 결과에 답변이 없으면 명확한 기본 안내를 표시한다.
- 사이드바의 대화 초기화 버튼은 메시지만 비운다. 캐시된 모델·DB 연결은 유지한다.

## Verification

- 테스트에서 가짜 Supervisor를 주입해 질문이 올바른 입력 형식으로 전달되고 `final_answer`가 추출되는지 확인한다.
- 빈 답변과 실행 예외가 사용자용 메시지로 변환되는지 확인한다.
- 관련 테스트와 전체 프로젝트 테스트를 실행한다.
- 가능하면 Streamlit 앱이 시작되는지 headless 방식으로 확인한다.
