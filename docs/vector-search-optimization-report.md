# VECTOR 검색 초기 이슈 및 최적화 결과

## 1. 작업 개요

- **대상:** 농업 GraphRAG 프로젝트의 VECTOR 검색
- **검색 구성:** Neo4j `chunk_embedding` Vector Index + `BAAI/bge-m3` (1024차원, cosine)
- **평가 범위:** 전체 골든셋 67문항 중 REJECT 10문항은 검색 평가 대상에서 제외. VECTOR 평가 대상은 19문항
- **작업 목적:** VECTOR 검색에서 정답 청크의 Top-K 누락 원인을 확인하고, Reranker 적용 및 후보 수 조정으로 적중률을 개선
- **코드 공유:** `codex/vector-memory-rerank` 브랜치에 평가·진단 코드와 메모리 계측 관련 의존성 정리 후 푸시

## 2. 초기 이슈

### 2.1 Neo4j 연결 및 평가 실행 환경 문제

재평가 초기에는 다음과 같은 오류로 결과 파일을 생성하지 못했다.

- `PermissionError [WinError 10013]`
- `ServiceUnavailable: Unable to retrieve routing information`
- `Failed to DNS resolve address ... [Errno 11001] getaddrinfo failed`

로컬 Windows PowerShell에서 DNS 조회와 TCP 7687 포트 접근에 성공했고, 프로젝트의 `.venv` Python 환경에서도 `driver.verify_connectivity()`를 통과했다. 따라서 **로컬 Neo4j 접속 자체는 정상**으로 확인됐다. 실패했던 재평가/진단 실행 환경과 로컬 환경의 차이가 의심되어, Neo4j가 필요한 평가는 **로컬 PowerShell에서 직접 실행**하는 방식으로 진행했다. 오류의 단일 근본 원인이 완전히 입증된 것은 아니다.

### 2.2 초기 VECTOR 검색 성능

초기 평가에서 VECTOR 19문항의 적중률은 다음과 같았다.

| 지표 | 초기 결과 | 비율 |
|---|---:|---:|
| Hit@1 | 10/19 | 52.63% |
| Hit@3 | 13/19 | 68.42% |
| Hit@5 | 14/19 | 73.68% |
| Hit@10 | 15/19 | 78.95% |

**Hit@10 실패 문항:** `GS039`, `GS045`, `GS056`, `GS065` (총 4문항).

이들 문항에서는 정답 `chunk_id`와 `evidence_id`가 기존 Top-10 결과에 나타나지 않았다. 별도로 라우터의 실제 선택이 예상 VECTOR와 달랐던 문항도 있었지만, VECTOR 검색의 적중 여부와 라우팅 정확도는 분리해 분석했다.

## 3. 원인 진단

### 3.1 데이터와 인덱스 검증

실패한 네 문항의 골든셋 정답 청크를 Neo4j에서 읽기 전용으로 조회했다.

| 문항 | 정답 청크 ID | 존재 | 임베딩 | 차원 |
|---|---|---|---|---:|
| GS039 | `CHK_4F546D431E569017` | 정상 | 존재 | 1024 |
| GS045 | `CHK_8C8BC08707CDEC1E` | 정상 | 존재 | 1024 |
| GS056 | `CHK_44B1292296567DF6` | 정상 | 존재 | 1024 |
| GS065 | `CHK_1EC914BFEBF6F238` | 정상 | 존재 | 1024 |

- 인덱스 `chunk_embedding`: **ONLINE**
- 대상 레이블/속성: `Chunk.embedding`
- 임베딩 모델 설정: `BAAI/bge-m3`, 1024차원, cosine

즉, 정답 노드 누락·임베딩 미저장·차원 불일치는 초기 실패의 원인이 아니었다. 다만 노드 및 임베딩 존재만으로 인덱스의 실제 반환 여부까지 보장되지는 않는다.

### 3.2 문항별 문제

| 문항 | 진단 결과 | 해석 |
|---|---|---|
| **GS039** | 기존 Top-10에는 없었으나, 확대 진단에서는 정답이 **1위**, cosine **0.817992** | 평가 실행 시점·검색 K 또는 ANN 결과 차이 가능성. 과거 질의 벡터가 저장되지 않아 원인은 확정되지 않음 |
| **GS045** | 정답 Top-100 밖, 기존 직접 cosine **0.758800** | 정답 청크의 임베딩 입력에 `양파`와 `잎마름병` 명칭이 빠져 있어 검색 표현 부족 가능성 |
| **GS056** | 정답이 벡터 검색 **25위**, cosine **0.820347** | 정답은 검색되지만 Top-10에서 제외되는 순위 문제 |
| **GS065** | 정답 Top-100 밖인데 직접 cosine **0.811460**; 직접 점수 기준 비교 집합에서 **2위** | ANN 후보 누락 의심. 반복 검색 5회 모두 정답 미반환; 정확한 내부 원인은 미확정 |

**GS045 메타데이터 실험:** 원본 메타데이터에서 작물명과 병해명을 보강한 텍스트의 대체 임베딩을 만들었더니, cosine이 **0.758800 → 0.853907**로 증가했다. 기존 ANN 후보 집합을 활용한 *가상 순위*도 101위 → 1위로 계산됐다. 이는 **프로덕션 인덱스에 새 임베딩을 등록해 실측한 결과가 아니다.**

**GS065 반복 실험:** 동일한 조건의 ANN 검색 5회에서 정답이 **0/5회** 반환됐다. 후보 누락 현상은 재현됐으나 엔진 내부 원인은 확정하지 못했다.

## 4. 개선 실험

### 4.1 Top-50 후보에 Reranker 적용

VECTOR 19문항 각각에 Top-50 검색 후보를 확보하고 CPU Reranker를 적용했다.

| 지표 | 초기 Top-10 | 현재 Vector Top-50 기준 | Top-50 + Reranker |
|---|---:|---:|---:|
| Hit@1 | 10/19 | 11/19 | **13/19** |
| Hit@3 | 13/19 | 14/19 | **15/19** |
| Hit@5 | 14/19 | 15/19 | **16/19** |
| Hit@10 | 15/19 | 16/19 | **17/19** |

검색 후보 확대/실행 시점 변화와 Reranker의 효과를 혼동하지 않도록 현재 Top-50 기준과 재정렬 결과를 별도로 비교했다. 전체 순위 변화는 **상승 5문항, 하락 2문항, 유지 10문항, 비교 불가 2문항**이었다.

- **GS056:** 정답 순위 **25위 → Reranker 1위**로 개선
- **GS034:** 정답 **1위 → 4위**로 하락. 중복 청크를 제거해도 순위 개선은 없었음
- **GS038:** 정답 **5위 → 10위**로 하락. 거의 동일한 안내 문구와 유사한 점수로 동점 처리 필요성이 발견됨

### 4.2 후보 수별 실제 CPU 재평가

기존 Top-50 후보를 각각 10·20·30·50개로 잘라, 한 프로세스에서 Reranker를 한 번 로드한 뒤 **각 후보 수마다 실제 CPU 추론**을 수행했다.

| 후보 수 | Hit@1 | Hit@3 | Hit@5 | Hit@10 | 평균 추론/문항 | P95 | 추론 합계 |
|---|---:|---:|---:|---:|---:|---:|---:|
| Top-10 | 13/19 | 14/19 | 15/19 | 16/19 | 7.07초 | 15.47초 | 134초 |
| Top-20 | 12/19 | 14/19 | 15/19 | 16/19 | 12.59초 | 24.77초 | 239초 |
| **Top-30** | **13/19** | **15/19** | **16/19** | **17/19** | **20.35초** | 54.34초 | 387초 |
| Top-50 | 13/19 | 15/19 | 16/19 | 17/19 | 27.35초 | 47.67초 | 520초 |

**Top-30의 선택 이유:** Top-50과 동일한 Hit@1·3·5·10을 보이면서 문항당 평균 추론 시간이 **27.35초 → 20.35초(약 25.6% 감소)**로 짧았다. 특히 GS056의 정답은 벡터 25위이므로 Top-20 이하로는 해당 정답을 후보에 포함시킬 수 없었다.

**비용 측정 주의:** 위 P95는 각 설정의 단일 19문항 측정치다. 순차 실행 순서와 CPU 부하가 영향을 줄 수 있어 반복 벤치마크 없이 일반화할 수 없다. 네 설정 통합 실행의 **최대 RSS는 2,186.7 MiB**였으며, 개별 후보 크기의 독립 피크는 아니다. 모델 로딩은 약 **62.65초**였고, 한 번 로드해 재사용하는 방식이 적절하다고 판단했다.

### 4.3 동점 처리 및 중복 제거

- **GS038:** Reranker 점수를 **소수점 3자리 버킷**으로 묶고 동점은 기존 VECTOR 순위로 정렬한 *저장 점수 후처리 실험*에서 정답 순위가 **10위 → 5위**로 상승했다.
- 이 후처리에서 전체 **Hit@5가 16/19 → 17/19**로 개선됐으며 Hit@1·3·10은 유지됐다.
- **GS034:** 동일 문서·근거·본문의 중복 청크를 합쳐 **50 → 48개** 후보로 줄였지만 정확도와 정답 순위(4위)는 변하지 않았다.

동점 처리는 별도의 모델 추론 없이 저장된 점수로 실험했으므로, 실제 검색 파이프라인에서 동일한 효과가 나타나는지는 추가 검증이 필요하다.

## 5. 최종 성능 정리

오프라인에서 가장 적절한 설정은 **Top-30 후보 + Reranker + 동점 점수 3자리 버킷 처리**로 판단했다.

| 지표 | 초기 VECTOR | Top-30 + Reranker | 동점 처리 실험 반영 시 |
|---|---:|---:|---:|
| Hit@1 | 10/19 (52.63%) | 13/19 (68.42%) | **13/19 (68.42%)** |
| Hit@3 | 13/19 (68.42%) | 15/19 (78.95%) | **15/19 (78.95%)** |
| Hit@5 | 14/19 (73.68%) | 16/19 (84.21%) | **17/19 (89.47%)** |
| Hit@10 | 15/19 (78.95%) | 17/19 (89.47%) | **17/19 (89.47%)** |

기본 Top-30 Reranker 성능은 직접 측정한 결과이고, **동점 처리 열은 저장 점수 기반 별도 후처리 실험 결과**다. 두 실험의 차이를 유지해 기록했다.

## 6. 남은 한계 및 적용 상태

1. **GS045:** 메타데이터 보강 임베딩의 유사도 향상은 확인했으나, 실제 프로덕션 인덱스 반영 및 검색 순위 측정은 수행하지 않았다.
2. **GS065:** ANN 반복 검색에서 누락 현상을 확인했지만 내부 근본 원인은 확정되지 않았다.
3. **실행 비용:** Top-30의 평균 CPU 재정렬 시간은 20.35초/문항으로, 실시간 서비스에서는 지연을 고려해야 한다. 모델을 프로세스별로 중복 로드하면 메모리도 별도로 필요하다.
4. **적용 범위:** Reranker와 동점 처리의 **오프라인 실험은 완료**했으나, 실제 서비스 검색기에는 적용하지 않았다. 최종 통합 서비스 성능으로 해석해서는 안 된다.
5. **평가 규모:** VECTOR 19문항의 결과이므로 더 큰 평가셋에서의 일반화는 아직 확인되지 않았다.

## 7. 작업 결과 요약 (팀 보고용)

1. VECTOR 검색 초기 Hit@10 실패 4문항을 진단하고, 정답 청크·임베딩·Neo4j 인덱스의 저장 상태가 정상임을 확인했다.
2. **Top-30 Reranker**가 VECTOR 19문항에서 **Hit@1/3/5/10 = 13/19, 15/19, 16/19, 17/19**를 기록했다.
3. Top-30은 Top-50과 동일한 적중률을 유지하면서 평균 CPU 추론 시간을 **27.35초에서 20.35초**로 낮췄다.
4. 동점 처리 실험으로 GS038의 순위가 **10위 → 5위**로 개선됐고, 중복 제거는 정확도 변화를 만들지 못했다.
5. GS045의 임베딩 입력 정보 부족과 GS065의 ANN 후보 누락 가능성을 추가 진단했다.
6. 평가·진단 코드 및 메모리 계측 의존성을 정리해 **`codex/vector-memory-rerank`** 브랜치에 푸시했다.
